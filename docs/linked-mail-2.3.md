# AgentDesk 2.3: общая проектная почта

## Что синхронизируется

Одинаковые поручения, статусы задач, назначения, ACK и файлы проектных папок `mail` на связанных AgentDesk. Почта здесь означает файлы/сообщения агентов, **не обычный e-mail аккаунт**. IMAP/SMTP не требуется и не реализован.

Оба ПК должны иметь 2.3.0 и быть уже связаны через «Другие компьютеры». Обмен идёт пока приложение запущено и ПК доступны друг другу. Недоступность, старый протокол и ошибки записи показываются во вкладке «Почта»; совпадение папок/файлов само по себе не выдаётся за ACK агента.

Не синхронизируются config.json, пароли, ключи, локальные пути и настройки автозапуска. Проекты со старым текстовым именем получают одинаковую детерминированную identity; для новых явно разделённых проектов можно передавать согласованный project_id. Одинаковое имя проекта рассматривается как одна общая почта — не используйте одно имя для независимых проектов.

## Папки

По умолчанию берутся существующие папки `mail` рядом с `monitor/inbox` каждого настроенного проекта. Другие произвольные папки не просматриваются. В «Файл → Папки общей почты…» можно явно задать локальные пути на каждом ПК. Пустой явно сохранённый список отключает файловый обмен.

- Максимум 8 МиБ на файл, 2000 подходящих файлов на root; размер фрагмента 64 КиБ.
- Обе стороны проверяют пути, SHA-256 и обычные файлы. Символические ссылки/junctions, скрытые/системные/временные и secret-подобные имена исключены.
- Изменения существующего файла применяются только при совпавшей базовой версии. Иначе обе версии сохраняются, конфликт виден.
- Резервные копии обновлений остаются локально. Удаления не распространяются: синхронизация не должна внезапно уничтожать почту.
- Временные фрагменты сохраняются отдельно; после рестарта передача может продолжаться, неполный файл не появляется в общей папке.

## Карточки, квитанции и маршрутизация

`task_id` — одна задача на весь цикл. `message_id` — UUID конкретного поручения/сдачи. `event_id` — identity события; повтор использует тот же ID. `AD-n` — только удобная локальная подпись.

Перед названием задачи отображается номер её карточки. Для задач со связанным напоминанием используется его исходный локальный AD/AB-номер; для задач без сообщения — AT-номер. Подпись сохраняется в локальном состоянии и не меняется при сортировке, пересдаче или перезапуске. На разных ПК локальные номера могут различаться; общий task_id остаётся UUID. В раскрытом списке квитанций видны и короткий номер сообщения, и его UUID.

Доставка на доску не означает чтение агентом. ACK снимает действие получения, но не принимает работу. Задача имеет состояния assigned/working/submitted/accepted/rework/blocked. Новое назначение и handoff подтверждает координатор задачи; epoch растёт, прежняя сессия не может сдавать работу за новую.

Из старых напоминаний создаются отдельные консервативные карточки: статус приёмки и реальное назначение не угадываются. Старые локальные AD/AB ACK остаются совместимыми только при соответствии проекта и получателя. На межкомпьютерных пересылках используйте UUID.

История синхронизации не обрезается вместе с коротким UI-журналом. Сейчас она хранится в state.json и может расти; не удаляйте журнал/курсоры вручную. Потеря локального журнала обнаруживается по его поколению, связанный ПК делает replay сохранённых событий. Это не замена резервному копированию всех компьютеров.

## CLI и MCP в Windows-установке

В папке установленного приложения находятся:

- `agentdesk.cmd` — CLI без отдельного Node.js;
- `agentdesk-mcp.cmd` — официальный MCP stdio-сервер над тем же Agent API.

Пример (путь установки может отличаться):

```powershell
& 'C:\Program Files\Agent Desk\agentdesk.cmd' inbox --project Demo --agent Ret
& 'C:\Program Files\Agent Desk\agentdesk.cmd' read --id '<UUID>'
& 'C:\Program Files\Agent Desk\agentdesk.cmd' ack --project Demo --agent Ret --session-id ret-session --message-id '<UUID>'
```

Из исходников: `node agent-desk/core/cli.js --help`. Поручения/submit можно подавать JSON через stdin, --file или --json. Ошибки имеют JSON-ответ и ненулевой код выхода. CLI не пишет state.json вторым процессом; приложение должно быть запущено.

MCP-клиенту укажите запуск `agentdesk-mcp.cmd` в соответствии с его Windows-инструкцией. Ключ агентского API отдельный, автоматически читается локально; не вставляйте ключ телефона/пароль в настройки клиента. Agent API доступен только с loopback и не принимает браузерный Origin. Если клиент не поддерживает запуск .cmd непосредственно, используйте его штатный механизм Windows command wrapper.

## Передача контекста

«Передать…» сохраняет новую сессию/устройство/роль и checkpoint, затем получает текст с сервера. Проверки Git выполняются только локально, без fetch и исполнения shell-команд. Remote-tracking ref — **кэшированное локальное свидетельство**, а не онлайн-проверка GitHub.

В «Папки контекста» явно разрешите репозитории и папки выбранных skills на этом устройстве. Эти разрешения не синхронизируются. Подписи/hashes артефактов и выбранных skills сверяются; подозрительный/секретный текст исключается, непроверенные данные так и подписываются. Большой контекст ограничен; не трактуйте обрезанный/отклонённый пакет как подтверждённое продолжение.

Адаптеры клиентов пока имеют честный `needs_manual_launch`: наличие доставленного поручения и MCP не доказывает, что конкретный агент автоматически начал новый ход. Для автоматического запуска нужен поддерживаемый API конкретного клиента и его настройка; произвольные команды из почты не исполняются.

## Безопасность соединения

Новый /p2p/sync передаёт содержимое в AES-256-GCM, с проверкой целостности и directional pair key; ключ не отправляется заголовком этой операции. Доверие — группе уже связанных устройств. Первоначальное pairing и старый phone/LAN HTTP оставлены совместимыми и **не заменяют TLS**. Связывайте компьютеры в доверенной сети; не выставляйте порт напрямую в интернет. Нельзя считать эту модель криптографической идентификацией каждого человека/агента внутри доверенного ПК.

## Установка и откат

Перед обновлением сохраните `%USERPROFILE%\AgentDesk\config.json` и `state.json`, закройте старую программу и установите 2.3.0 на **оба** ПК. Не запускайте две доски на одной папке маркеров. Данные сохраняются, UUID/карточки мигрируют при первом успешном запуске. Для отката закройте новую программу, верните резервные config/state и установите старую версию; не смешивайте живой журнал разных версий.

Android web-интерфейс подготовлен общим кодом. APK требует штатной сборки Android/JDK и отдельной проверки; этот документ не утверждает, что APK собран или установлен.
