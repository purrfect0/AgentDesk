## HTTP API (parent implements, all JSON)

GET /api/agent/inbox?project=&agent=&session_id= -> {todos, tasks, device_id}; GET /api/agent/read?id=<message or task id> -> {todo?,task?}; POST /api/agent/submit -> validated marker, {ok,event_id,task_id,message_id?}; POST /api/agent/ack -> {agent,project,session_id?,message_id}, receipt only, not task completion. GET /api/agent/status -> {tasks,bindings,device_id}; POST /api/tasks/assign, /transition, /handoff -> bodies TaskService methods; GET /api/tasks/context?id= -> {text,task,checks}. GET /api/mail -> mail payload. POST /api/mail/config -> {roots:[{project,path}]} local admin only.

CLI/agent API uses separate local agent key via X-Agent-Desk-Agent-Key; parent allows only loopback agent auth and requires it for /api/agent routes, not broad admin access. Same-origin UI owner remains allowed to /api/tasks and /api/mail; CLI task mutations routed /api/agent/task/assign|transition|handoff and context GET /api/agent/context. `agent-client.js` reads only config.port and config.agent_key (never full output), defaults AGENT_DESK_HOME or ~/AgentDesk, --server only loopback http to avoid key exfiltration. Adds X-Agent-Desk:1 on POST. Errors JSON on stdout and nonzero exit. CLI inbox/read/ack/submit/status/handoff/context/assign/transition; input JSON via stdin or --file plus flags, no direct state.json mutation.

MCP thin stdio tools using same client. Prefer official maintained SDK; do not edit package.json in child. Tell parent exact dependencies. No custom JSON-RPC implementation. Smoke/test mock HTTP on loopback with temp config. CLI supports `serve` optional headless Desk(port override env, lan=false default) if useful but not required.

## MailStore ownership (core/mail.js)

Export MailStore class(desk). Parent imports and instantiates after config/state loaded. Roots explicit desk.config.mail_roots OR infer existing sibling ../../mail from config.watch (only directory named monitor/inbox; otherwise none). payload() -> {roots,files,errors}. scan() returns change boolean; saves only state.mail_index metadata, parent _tick then _saveState. manifest() -> rows {project,path,sha256,size,previous_hash?}; readChunk({project,path,sha256,offset}) -> {data(base64),offset,total,sha256,next}; acceptChunk(peer,{project,path,sha256,previous_hash?,offset,total,data}) -> {ok,complete,...} writes only configured safe root, atomic chunk staging. Max 64 KiB raw chunk, file limit 8 MiB. Parent p2p encrypted sync exchanges manifests then pull missing chunks. Never follow symlinks/junctions or traversal, no arbitrary absolute paths from remote. Only regular files, skip hidden/system/.git/.tmp and secret-ish files; max file counts bounded. If destination changed concurrently, preserve both, deterministic conflict name and visible error; no remote deletion. Only replace if destination equals declared previous_hash and keep recoverable backup. Full hash verification before install; staging paths internal and named by hash+peer+project/path. Disk failure must throw/no success. Test traversal, symlink, duplicates, chunks ordering, hash mismatch, concurrent conflicts, roots mismatch, safe updates/offline manifest, no deleting user files. Child may write core/mail.js and core/test/mail.test.js plus mail docs only.

## Parent sync engine

Encrypted per-pair AES-GCM authenticated request/response on /api/p2p/sync, no bearer key sent in clear on this route. Existing pairing remains LAN pairing. Persistent immutable entity journal in state.sync, per-peer paging/cursors, Lamport version deterministic resolution; sync todo/task/binding/agent snapshots not configs/passwords/paths. Independent durable import, dedup after closure/restart, no receive echo. Includes all events for new paired peer replay. Per-event receipts only after disk save, no SMTP/IMAP implementation. Pull safe mail chunks over authenticated encrypted requests. ACK from wrong project/recipient/stale seq rejected. No close on board delivery. Old protocol peers shown unsupported and retain legacy manual forwarding, no false claims of full sync.
